# WF-20260517-project-adapter

## Status
approved

## Intent
Make the OpenCode TDD workflow reusable as a greenfield starter kit by separating generic workflow assets from project-specific configuration while avoiding adoption of existing product/test/CI layouts.

## Scope
- Add a required project adapter at `.opencode/project.json`.
- Add `/init-project` and an `init-project` skill for mandatory post-copy initialization.
- Limit `/init-project` to empty/docs-only product repositories via a Greenfield Gate.
- Replace legacy global acceptance IDs with feature-scoped `test_case_id` values such as `RENT-001`.
- Split acceptance criteria into one markdown file per feature under `docs/acceptance/`.
- Replace the generated feature manifest with a generated test-case manifest.
- Move project-specific agent permissions behind templates rendered by initialization.
- Update workflow docs, skills, agents, state examples, and commands to use the new contract.

## Source Of Truth Changed
- Project-specific workflow binding moves to `.opencode/project.json`.
- Human acceptance criteria move to `docs/acceptance/*.md`.
- Machine acceptance lookup moves to `.opencode/state/test-case-manifest.json` generated by `.opencode/scripts/build-test-case-manifest.mjs`.
- Workflow-kit ownership is tracked by `.opencode/workflow-kit.json`.
- Target project scope is greenfield-only; existing product repos require a separate migration workflow.
