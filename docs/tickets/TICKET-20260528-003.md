# Refactor Runner Normalization And Policy Dispatch

## Goal
Split runner behavior so strict TDD remains unchanged while exploratory and light-check workflows can become local first-class execution paths.

## Scope
- Normalize legacy `workflow_mode` into `workflow_stage` and `quality_policy`.
- Keep strict-TDD FSM behavior compatible.
- Select ticket executability from `quality_policy`.
- Add a lightweight `workflow-maintenance` executor that dispatches `workflow-engineer`.
- Defer ready tickets with unmet `depends_on` instead of marking them malformed.

## Validation
- `workflow-maintenance` + `light-checks` tickets dispatch only to `workflow-engineer`.
- `workflow-maintenance` completion rejects dirty product roots.
- Inline and block-list `depends_on` frontmatter both parse.
- Strict-TDD tickets still follow the existing RED/GREEN/review FSM.

## Definition Of Done
- `workflow-runner.mjs --json` reports stage and policy clearly.
- Strict-TDD tickets still follow the existing RED/GREEN/review FSM.
- Non-strict tickets do not require `test_case_id`.
- Workflow-maintenance execution validates workflow-engineer output before completion.
