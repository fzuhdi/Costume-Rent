# Normalize Workflow Schema To Stages And Quality Policies

## Goal
Replace generated `workflow_mode` usage with a clearer local ticket model:

```yaml
workflow_stage: design-ui | integrate-backend | deployment | workflow-maintenance
quality_policy: exploratory | light-checks | strict-tdd
```

## Scope
- Update `.opencode/project.json` and `.opencode/project.example.json` with product stages, internal stages, quality policies, defaults, and legacy mode mapping.
- Keep legacy `workflow_mode` readable through normalization.
- Preserve `max_parallel` and runtime lease settings outside the stage/policy taxonomy.

## Validation
- JSON parsing and config normalization accept the new fields.
- Legacy `workflow_mode` values normalize to the expected stage/policy pair.
- Doctor/portability checks validate the new fields.

## Definition Of Done
- Project adapter exposes stage and quality policy fields.
- `workflow-maintenance` is documented as internal-only.
- Legacy config remains readable.
- Product-facing stage language remains `Design UI -> Integrate Backend -> Deployment`.
